# EU-accessible retail brokers for automated trading of real shares/ETFs with a tiny account (Poland resident, October 2026)

Research date 2026-10-31. Scope: official order-placement APIs only, real shares/ETFs (not CFDs), non-professional retail client tax-resident in Poland, starting capital about 20 USD (up to a few hundred or ~1,000 USD later), host with ~700 MB free RAM. Alpaca excluded. Items already settled in the brief (Trading 212, DEGIRO, XTB, Plus500, Webull, TradeStation Europe, IBKR fee basics) are not re-researched. Evidence tags: [H] primary vendor document or terms fetched on 2026-10-31, [M] reputable secondary or vendor claim consistent with other evidence, [L] single anecdote, aggregator, vendor marketing, or old. "Undated" means the fetched page carried no date.

Pages from ibkrcampus/interactivebrokers.com returned 403 to WebFetch but were retrieved with curl/Exa; content below is from those fetches.

## 1. Interactive Brokers (IBKR Ireland): which API path works on a headless ~700 MB host, and what a 20 USD account costs

### Takeaway
For an individual account IBKR officially supports only the Java Client Portal Gateway (REST) or TWS/IB Gateway (socket); OAuth 2.0 is documented for organisations/advisors only, and OAuth 1.0a for individuals is contested (IBKR docs and some support agents say no; the ibind project and many users report that the self-service portal works). Gateway-based paths (JVM, daily or weekly 2FA, IBeam adds Chromium and Xvfb) are incompatible with a 700 MB host, so IBKR is only viable if OAuth 1.0a self-service really works on the owner's account. On cost, the 1% per-order cap makes 20 USD orders cost about 0.20 USD (about 1% per side), but fractional shares are NOT available through any IBKR API (whole shares only) and market-data subscriptions require 500 USD equity.

### Cited Findings

API types and who may use them
- IBKR Web API doc: "Web API usage for individual clients involves an IBKR username and password"; live account must be fully open and funded to use the Web API on live or on its paper account; the account must be "IBKR Pro". [H] — [IBKR Web API docs](https://www.interactivebrokers.com/campus/ibkr-api-page/webapi-doc/) (undated page, fetched 2026-10-31)
- The Client Portal Gateway "is a Java client that reverse-proxies authentication through SSO" and is the supported method for Individual Accounts; OAuth 1.0a is listed for Advisor, Broker/FCM, Prop trading, Hedge fund, Institutional hedge fund investor and Third-Party developer accounts; OAuth 2.0 for Advisor, Broker/FCM, Prop, Hedge fund, Institutional hedge fund investors. [H] — [IBKR authentication intro](https://www.interactivebrokers.com/docs/web-api/authentication/introduction.md)
- OAuth 2.0 (labelled "beta") is "for licensed Organizations, Financial Advisors, and IBrokers"; tokens allow calls directly to api.ibkr.com without the Client Portal Gateway; "Beyond the initial authentication procedure, the OAuth implementation will behave the same as the standard Client Portal Gateway". [H] — [OAuth 2.0 intro](https://www.interactivebrokers.com/docs/web-api/authentication/oauth-2/introduction.md); [Web API docs](https://www.interactivebrokers.com/campus/ibkr-api-page/webapi-doc/)
- Third-party vendors may only seek OAuth 1.0a approval; the process is 2-3 weeks screening plus 3-6 weeks compliance plus 3-5 weeks legal. [H] — [Web API docs](https://www.interactivebrokers.com/campus/ibkr-api-page/webapi-doc/)
- OAuth 1.0a for individuals is contested: an IBKR support reply quoted in ibind issue #49 (undated, c. 2025): OAuth available "only for ORG and FA accounts"; OAuth 2.0 "not yet available as a usable service for individual accounts... no timeline". A user in ibind issue #98 (2025-04-21) got HTTP 403 when uploading the DH parameters on an individual account, and IBKR support told them OAuth is for advisor/institutional only. [M] — [ibind issue #49](https://github.com/Voyz/ibind/issues/49); [ibind issue #98](https://github.com/Voyz/ibind/issues/98)
- Counter-evidence: the ibind docs state "indeed it seems to be possible to use OAuth 1.0a on individual accounts. Many individual account users reported successfully registering both live and paper credentials" and quote an IBKR API support agent: "I'm not aware of any technical limitations which would prevent an individual accountholder from accessing the OAuth 1.0a self-service portal (in either paper/live mode)". Setup: RSA keys + DH params uploaded at the IBKR self-service OAuth page; keys activate only after the weekend server restart (reports range from overnight to two weeks). [M] — [ibind OAuth 1.0a doc (mirror)](https://www.webkkk.net/Voyz/ibind/blob/master/docs/oauth/oauth_1a.md); a user reports the keys "will bypass 2FA" [L] — [blog](https://marchenko1985.github.io/ibkr-api-oauth/); a vendor (Ordertune) claims it works for all Pro individual accounts, no daily re-auth [L, vendor] — [Ordertune](https://docs.ordertune.com/brokers/ibkr-pro-setup)
- The ibind library itself warns its OAuth 1.0a code relies on the unmaintained pyCrypto library. [M] — [ibind OAuth doc](https://www.webkkk.net/Voyz/ibind/blob/master/docs/oauth/oauth_1a.md)
- A third-party project (agentic-trading-mcp) concluded in an ADR that "Web API OAuth is not available to retail/individual accounts" and that retail can only use the gateway with manual 2FA login; it lists ~6 min session expiry without /tickle, ~24 h max session length, daily maintenance ~01:00 local. [L] — [DECISIONS.md](https://github.com/pedrobraiti/agentic-trading-mcp/blob/main/DECISIONS.md)
- TWS API: requires a funded IBKR Pro account, current Stable/Latest TWS or IB Gateway, Python >= 3.11 (client library), Java 21 for the Java client. [H] — [TWS API requirements](https://www.interactivebrokers.com/docs/tws-api/doc/notes-limitations/requirements.md)
- FIX is for institutions: minimum equity 10,000 USD to apply and a 1,500 USD/month minimum commission for the first session. [H] — [IBKR FIX requirements](https://www.interactivebrokers.com/docs/fix/requirements.md)
- IBKR's own overview states the unified "IBKR Web API" is converging on OAuth 2.0 while "Existing endpoints and authentication schemes are not deprecated". [H] — [Web API docs](https://www.interactivebrokers.com/campus/ibkr-api-page/webapi-doc/)

Session, 2FA and unattended operation
- A username can have only one brokerage session at a time across all IB platforms; the Web API session needs `/tickle`; `/iserver` (brokerage) functionality is unavailable briefly each evening ~01:00 local by region (Europe 01:00 CEST); Web API gets maintenance on Saturday evenings. [H] — [Web API docs](https://www.interactivebrokers.com/campus/ibkr-api-page/webapi-doc/)
- 2FA is mandatory for all users; supported for API login: IB Key, Handy Key, SMS, DSC+; unsupported: Security Code Card, Temporary Security Code Card, Online Code Card. [H] — [IBKR 2FA for API](https://www.interactivebrokers.com/docs/tws-api/doc/notes-limitations/supported-two-factor-authentication-2-fa.md)
- IBKR support (quoted 2022-12) on automating the gateway: "There is no means to disable Two Factor Authentication... the Web API authentication key resets every 24 hours, which can not be altered." Older than 12 months. [M] — [IBeam issue #118](https://github.com/Voyz/ibeam/issues/118)
- IBeam (the common headless wrapper for the Client Portal Gateway): uses Selenium + Chrome + a virtual display (pyvirtualdisplay) to type credentials into the gateway login page; "beta"; no RAM figure published; roadmap lists 2FA as unfinished; authors warn to "prepare for breaks in connectivity". [H] — [IBeam README](https://github.com/Voyz/ibeam)
- IBeam image installs `default-jre`, `chromium`, `chromium-driver`, `xvfb`, `xorg`, fonts, Python venv. [H] — [IBeam Dockerfile](https://github.com/Voyz/ibeam/blob/master/Dockerfile)
- IBeam issue #286 (undated): Chromium/crashpad zombie processes grow ~40-45/day (~300 after 7 days) unless the container runs with an init (`docker --init`). [M, single report] — [issue #286](https://github.com/Voyz/ibeam/issues/286)
- IBeam wiki: "authentication loop" where the gateway never reports authenticated; "no clear pattern... There's a good chance that for you it will break every other day"; IBKR 24-hour lockout after 10 consecutive failed logins. [M] — [IBeam Troubleshooting](https://github.com/Voyz/ibeam/wiki/Troubleshooting); [IBeam config](https://github.com/Voyz/ibeam/wiki/IBeam-Configuration)
- IBeam issue open 2026-04-30: IBKR changed the 2FA input field id on the live login page, breaking the 2FA step ("bronze" field). [M] — [IBeam issues](https://github.com/Voyz/ibeam/issues)
- IBeam open PR #282 (2026-04): author reports headless login with TOTP auto-entry worked on aarch64 with Debian Chromium. [L] — [PR #282](https://github.com/Voyz/ibeam/pull/282)
- A 2026-05 project (bezant) deliberately keeps the IB Key push human-held: its Playwright relogin service fills username/password but a person must tap Approve; session "ages out roughly every 24h". [L] — [bezant commit](https://github.com/isaacrowntree/bezant/commit/d62b91b3a55eda0390dd4a35ff9d1b060a05c602)
- TWS/IB Gateway auto-restart: IBKR 974 release notes say auto-restart lets users authenticate manually only once per week, each Sunday (quoted in a 2023 issue); IB Gateway + IBC reported by one user to need 2FA only on Sundays and to be more stable than the Client Portal Gateway. Older than 12 months. [M] — [IBeam issue #150](https://github.com/Voyz/ibeam/issues/150)

Rate limits
- Global 10 requests/second per authenticated username; penalty box 10 minutes for violating IPs; `/iserver/orders` and `/iserver/trades` 1 req/5 s, `/tickle` 1 req/s, `/portfolio/accounts` 1 req/5 s, `/iserver/marketdata/snapshot` 10 req/s; 429 on excess. [H] — [Web API docs](https://www.interactivebrokers.com/campus/ibkr-api-page/webapi-doc/)

Server-side order types
- Web API submit: orderType incl. stop (`auxPrice`), trailing (`trailingAmt`/`trailingType`), bracket via `parentId` = parent `cOID`, OCA via `isSingleGroup`; `tif` in DAY, IOC, GTC, OPG, PAX; `cOID` unique for 24 h, max 64 chars; `outsideRTH`. [H] — [Submit New Order](https://www.interactivebrokers.com/docs/web-api/api-reference/trading/trading-orders/submit-new-order.md)

Fractional shares via API

[H] — [IBKR Ireland fractional trading](https://www.interactivebrokers.ie/en/trading/fractional-trading.php) (undated, fetched 2026-10-31)

[H] — [cash quantity doc](https://www.interactivebrokers.com/docs/web-api/v1/endpoints/orders/cash-quantity-orders-in-the-web-api.md); [changelog 2026-03-27](https://www.interactivebrokers.com/docs/web-api/changelog/2026/3/27.md)

Market data

[H] — [IBKR minimum equity for market data](https://www.interactivebrokers.com/docs/general/market-data-subscriptions/market-data-subscription-minimum-equity-balance-requirements.md)

### Inferences
- Agent calculation from the fee table: a 20 USD whole-share US order at IBKR Pro Fixed costs min(max(0.005 x shares, 1.00), 1% x 20) = 0.20 USD, i.e. about 1% per side and about 2% round trip before spread and tiny regulatory fees; the same cap logic applies to Tiered. A 1,000 USD order costs about 1.00 USD (0.1% per side). So IBKR is the cheapest tiny-account option among full brokers, not the 5% per side one might assume from the 1 USD minimum. [M]
- The universe at 20 USD is limited to stocks/ETFs priced below ~20 USD (whole shares only through any IBKR API) — this undermines strategies that need arbitrary position sizing. [H on the API limitation, M on the consequence]
- With ~700 MB free RAM, swap already in use and a real-money bot sharing the host, any path that needs IB Gateway (JVM heap 768 MB default) or IBeam (JVM + Chromium + Xvfb) should be rejected; the Client Portal Gateway alone is unmeasured and still needs a daily human or scripted 2FA login. The only IBKR route that fits is a pure-Python OAuth 1.0a client (e.g. ibind), and it works only if IBKR enables self-service OAuth for this individual account — contested; test it before building. [M]
- If OAuth 1.0a works, keys must be set up on the funded live account (and separately on paper credentials), activate only after a weekend restart, and `/tickle` plus daily ~01:00 CEST brokerage-session maintenance must still be handled by the adapter. [M]
- A paper account is never available "for free": it requires a funded Pro live account, so the paper phase at IBKR already needs the live deposit (any amount; the 500 USD market-data threshold means no real-time data below that). [H]

### Gaps
- No measured RSS for Client Portal Gateway, IB Gateway or IBeam on a 1-vCPU/low-RAM host was found; must be measured on the VPS.
- Whether OAuth 1.0a self-service is enabled for a new IBKR Ireland (IBIE) individual Pro account in October 2026 is unverified (evidence is from 2025, mostly US/other entities).
- Whether free delayed market data is available through the API for accounts below 500 USD equity was not verified.
- IBKR Ireland's exact eligibility for Poland-resident clients and PLN as base currency were not re-verified here (brief states them as established).

## 2. Other candidates evaluated one by one (API, terms on automation, unattended operation, demo, costs)

### Takeaway
Only three candidates other than IBKR combine an official REST/WebSocket order API, permission for bots and no heavy runtime: eToro (public API, bots explicitly allowed, but high minimum deposit and per-trade stock commissions), tastytrade (OAuth2 REST + never-expiring refresh token, algorithmic use expressly permitted, but non-EU US broker, USD-only wire funding), and Saxo (OpenAPI REST/WebSocket, EU bank, but interactive OAuth with rotating refresh tokens and a 1 USD minimum commission). Kraken's new MiFID-licensed US-stock service for the EEA (live since 2026-08-18, Poland included) is promising but its API coverage for real stocks is unverified. Freedom24 has an API but its costs are prohibitive at tiny size; Exante, Swissquote, Bossa are blocked by size/professional/Windows limits; Lightyear, Scalable, Trade Republic, Revolut and Polish bank brokers have no usable retail order API.

### Inferences

**(a) Paper / demo phase (adapter validation, state machine, reconciliation)**
1. tastytrade sandbox — free, separate OAuth app, no KYC/live funding implied by the docs, same paths and payloads as production; caveats: REST market data 502, 24 h resets, simulator fills at quote mid (fills do not model queue/slippage), so it validates hydraulics (idempotency by `external-identifier`, order lifecycle, WebSocket recovery) but not costs. [H]
2. eToro Demo API — same endpoints with `/demo/`, demo keys separate from real keys, private:demo WebSocket stream; needs a verified (KYC) real account, funding not stated; execution realism is a vendor claim. [M]
3. Saxo SIM — free developer account and 24 h tokens, but equity prices only for products on a funded linked live account, SIM is lower-priority and has no market data/reporting, so equity paper trading effectively needs a funded live account. [M]
4. IBKR paper — needs a funded Pro live account first; if OAuth 1.0a works on paper credentials it is pure Python, otherwise JVM gateway. [M]
5. Exante demo exists but live is out of reach (EUR 50k for API): useless except as an exercise. [H]
6. Keep Alpaca paper (excluded for live) as the cheapest generic paper stack if the broker interface is broker-agnostic; broker-specific adapters need only a thin sandbox smoke test.

**(b) Tiny live phase (20 USD, later a few hundred to ~1,000 USD)**
1. IBKR Ireland — lowest cost per ticket thanks to the 1% cap (about 0.20 USD at 20 USD), no minimum deposit, EU regulation and Irish ICS; BUT whole shares only via API (stocks under ~20 USD), no real-time data under 500 USD equity, JVM gateway infeasible on this host, so conditional on a successful OAuth 1.0a test; fallback is to run the gateway elsewhere (not on this VPS). Highest regulatory comfort, highest operational uncertainty. [M]
2. tastytrade — $0 commission, best unattended auth, sandbox, explicit algo permission; main costs are USD wire funding/exit ($45 outgoing) and non-EU legal basis (KNF reverse solicitation, no EU compensation), and unclear fractional support; for 20 USD the exit cost exceeds the capital, so fine only if the money stays there. [M]
3. eToro — good API and terms, ETFs commission-free, but first deposit and minimum trade likely above 20 USD and exits cost $5 plus $30 minimum from the USD account; reasonable from ~200 USD with ETFs. [M]
4. Saxo — EU bank, no custody fee in Poland, clean API, 1 USD minimum commission (5% per side at 20 USD, 0.1% at 1,000 USD), unknown pre-fund threshold, weekly OAuth login; sensible from ~500-1,000 USD. [M]
5. Kraken — watch item pending API answer. [L]
6. Freedom24 — only from ~1,000 USD. [M]
